# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This is a **content repository**, not a software project. It contains daily news briefings ("Morning Download") as standalone Markdown files. There is no build system, test suite, linter, or application code — work here means authoring and editing Markdown.

Each briefing covers two beats: (1) world events / markets / M&A, and (2) AI and agentic systems. Briefings are generated by a scheduled "Daily News Brief" task and committed via PR.

## Layout

- `briefs/YYYY-MM-DD.md` — one file per day (e.g. `briefs/2026-05-29.md`).
- `briefs/YYYY-MM-DD-evening.md` — optional additional editions for a given day (suffix the edition name).

## Briefing format

The format has evolved; **match the most recent briefs** (`briefs/2026-05-*.md`) rather than older ones when authoring a new one. The current convention:

- Title: `# Morning Download — Month D, YYYY`, with `---` horizontal rules separating major blocks.
- `## Section 1: World & Market Briefing` — each item is a bolded headline prefixed with a topical emoji (🇪🇺 🏛️ 📊 🏦 💼), followed by analysis. Include one item explicitly marked **Wildcard**.
- `## Section 2: AI & Agentic Systems Briefing` — same emoji-headline format (🧠 🔮 🤖 🔌 📊 💡).
- `## Sleeper Story` — one under-covered story with a "why it matters" argument.
- `## One-Liner` — a single synthesizing sentence summarizing the day.
- `## Sources` — a bulleted list of `[Title — Publisher](url)` links backing the claims.

Each headline's body is analysis-forward: state the fact, then explain the second-order implication (often addressed to enterprise/builder readers). Older briefs (`briefs/2026-04-*.md`) used plain bullet lists with inline `**Why it matters:**` tags and a combined `## Closing` section — do not copy that style for new entries.

## Working conventions

- Dates in this repo are in 2026 (the news content is dated accordingly); do not "correct" them to the present.
- Sources should be real, working URLs that substantiate the headlines — every factual claim in a briefing should be traceable to the Sources list.
- One briefing per file; never edit a prior day's briefing to add a new day.
